# Summary

Phase 7 establishes Looker Studio as the reporting, semantic-modeling, interaction and governed-delivery
layer of the Google analytics ecosystem. The research separates source datasets, connectors, data
sources, reports, credentials, asset roles, blends, controls, publishing and audit boundaries.

# Official sources

Sixteen Evidence records use official Google Cloud Data Studio documentation. Mutable product behavior
was verified on 2026-07-14.

# Architecture

A report presents information derived from data and contains pages, charts, controls and explanatory
components. A data source connects external data to those components and defines the field schema used
for dimensions, metrics, parameters and calculated fields. A connector performs the source-specific
retrieval.

# Connection modes

Most data sources query the underlying dataset as needed. Extracted data stores an updatable static
snapshot. Embedded data sources belong to and travel with one report. Reusable data sources can serve
multiple reports and provide a shared semantic model. Community connectors expand source coverage but
remain third-party software with separate support, authorization, pricing and security boundaries.

# Credentials and access

Owner's credentials query through the data-source owner. Viewer's credentials require every viewer to
have direct access to the source dataset. Service-account credentials use a non-human Google identity.
These data credentials are independent from Viewer, Editor and Owner asset roles. Sharing a report or a
reusable data source therefore does not itself grant access to the underlying data.

# Calculated fields

Calculated fields derive new dimensions or metrics. Data-source calculated fields are reusable across
reports but cannot operate on blended data. Chart-specific calculated fields can use blended data, but
they remain local to one chart and cannot reference another chart-specific field.

# Blending

A blend can combine up to five data sources and is embedded in its report. It inherits freshness and
credential settings from the component data sources. Looker Studio aggregates each blend table before
the join, and join conditions support equality only. Missing unique identifiers can therefore collapse
rows and produce results that differ from a row-level SQL join.

# Filters and interaction

Editor-defined filter properties can apply at report, page or component scope. Viewer controls can
filter data, set parameters, change timeframes or choose datasets. Cross-source controls match internal
field IDs, not display names, so flexible-schema sources may require explicit field-ID unification.
Cross-filtering converts supported chart selections into filters for other charts.

# Sharing and embedding

Viewer, Editor and Owner roles progressively permit interaction, modification, sharing, deletion and
ownership transfer. Reusable-source viewers can inspect schema, editors can modify schema, and only the
owner can change the connection. Public and restricted reports can be embedded. Private embeds preserve
sign-in and access requirements, while embedded view mode supports interaction without edit, copy or
share actions.

# Publishing and lifecycle

Manual report publishing separates an editor draft from the current viewer-facing version. Version
history tracks current draft and published states. This boundary does not isolate reusable data-source
changes: source edits can appear in both draft and published reports without a new report publication.
Report and reusable-source change control must therefore be governed together.

# Governance conclusion

Looker Studio does not replace source-system access control, warehouse modeling or metric contracts.
Production reporting requires explicit ownership for datasets, connectors, credentials, field schemas,
blend grain, filters, publishing and reusable-source changes. Data Studio Pro audit logging adds Cloud
Audit Logs for supported administrative and data-access operations, but it is a paid-product boundary.
