# Scope and official sources

This report covers Android Vitals in Play Console and the Play Developer Reporting API only.
Canonical claims and provenance remain in Facts and Evidence.

# Android Vitals, crash, and ANR

Android Vitals covers stability, performance, battery, and related technical quality. User-perceived
crash/ANR rates are core vitals and remain separate from overall and multiple-event rates. Their
overall thresholds are 1.09% and 0.47%; both use 8% per-phone-model thresholds.

# Rendering and startup

Rendering metrics distinguish games-only slow sessions from UI Toolkit slow and frozen frames.
Startup uses TTID and cold/warm/hot states. Cold and warm thresholds are consistent; official pages
currently disagree on hot startup, so no canonical value is asserted.

# Battery, dimensions, thresholds, and alerts

Battery signals cover wakeups, background scans/network use, wake locks, and watch-face usage under
explicit collection conditions. Common UI breakdowns are artifact, SDK, form factor, device model,
and country. Core thresholds can affect Play visibility. Email alerts are documented for anomalies.

# Reporting API, export, history, and privacy

The API exposes metric sets and error resources with metadata/get and data/query operations. DAILY
data uses America/Los_Angeles; metric sets expose freshness and support filters, dimensions, rolling
rates, and token pagination. UI has 90 days; API has three years. Collection uses opted-in users from
a subset of devices/OS versions and excludes uncertified devices or non-Play installs. Detailed
crash/ANR bulk reports were retired in 2018; dedicated Vitals GCS or BigQuery export is not confirmed.

# Coverage, open questions, and next phase

Covered: core metrics, crash, ANR, startup, rendering, battery, common dimensions, thresholds,
alerts, Reporting API, history, freshness, pagination, quota, privacy population, and export boundary.
Open: hot-start threshold resolution, historical recalculation rules, all metric-specific dimensions,
sampling mechanics, anonymization beyond wake-up tags, and direct BigQuery/GCS availability.

Recommended next phase: Phase 1.7 — Google Play Console Final Consolidation. It has not started.
