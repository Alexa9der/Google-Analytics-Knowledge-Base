# Summary

Phase 5 establishes Google Analytics 4 as the property, processing, reporting, attribution, API, and
integration layer of the ecosystem. It connects website and app collection to identity, key events,
consent, product links, report surfaces, and event-level BigQuery export.

# Property and collection architecture

```text
Website or app
→ web, iOS, or Android Data Stream
→ event-based collection
→ GA4 property
```

A property can combine website and application data. Realtime is the first surface for verifying new
collection. Standard reports appear after further processing. The Data API reads report data, while
the Admin API manages property configuration.

# Reports and Explorations

Reports provide recurring overview and detail analysis. Explorations provide advanced ad hoc
techniques, segmentation, filters, drill-down, audiences, sharing, and export. The surfaces are not
interchangeable: supported fields, filter semantics, retention, thresholds, sampling, and processing
time can produce different outputs.

# Reporting identity

Reporting identity defines which identity spaces GA4 uses to unify and de-duplicate users. Blended,
Observed, and Device-based options affect report results without rewriting collection or permanently
modifying the underlying event data.

# Attribution and key events

Attribution assigns key-event credit to eligible touchpoints. GA4 settings control the reporting
model, eligible channels, and lookback window. Direct traffic normally receives no credit unless the
path contains only direct visits. Report-layer attribution is distinct from raw BigQuery event rows.

# Consent and privacy controls

Consent mode communicates consent state to Google tags and changes collection behavior. Eligible
advanced implementations can send cookieless pings used for behavioral and conversion modeling.
Privacy thresholds can withhold report output when disclosure could increase identification risk.
Threshold values are system-defined rather than user-configurable.

# Retention

Standard properties support 2- or 14-month retention for user- and event-level data. Retention affects
Explorations and funnel analysis but does not remove standard aggregated reports on the same schedule.
A retention change has a documented implementation delay.

# Measurement Protocol

Measurement Protocol sends trusted server-side and offline events over HTTP. Web requests use
`measurement_id` and `client_id`; app requests use `firebase_app_id` and `app_instance_id`. An
`api_secret` must remain in a trusted environment. Measurement Protocol supplements, rather than
replaces, normal tagging or Firebase SDK collection.

A request can contain up to 25 events, with up to 25 parameters per event. Events can be backdated up
to 72 hours. `session_id` and `engagement_time_msec` are important when server events must contribute
to session, engagement, and Realtime metrics. The validation endpoint returns structured issues but
does not collect debug events as production data.

# Product integrations

## Firebase

One Firebase project links to one GA4 property, and all applications in that project send Analytics
data to the linked property. Enhanced audience integration supports audience prepopulation and
advanced audience export. Unlinking stops future application data flow.

## Google Ads

A Google Ads link exchanges campaign data, audiences, and key events. It requires permissions in both
products, and linked data can take up to 48 hours to appear. Unlinking stops future integrated use but
does not erase all previously collected historical dimensions.

## Search Console

The Search Console integration links one GA4 web stream to one Search Console property and provides
Google Organic Search Queries and Google Organic Search Traffic reports. The integration has a
16-month history limit, an approximately 48-hour delay, restricted dimension compatibility, and
one-to-one link cardinality.

## BigQuery

GA4 supports Daily and Streaming export; Analytics 360 can additionally use Fresh Daily export.
Export configuration can select streams and exclude events. Standard Daily export has a one-million-
event limit per day, while Streaming export does not use that event-count limit.

# Why GA4 surfaces differ

```text
Reports / Explorations / Data API
→ report data
→ reporting identity
→ aggregation
→ attribution and modeling
→ privacy thresholding
→ possible sampling
→ possible (other) row

BigQuery
→ granular event and user rows
→ no report-layer data-driven attribution result
→ no key-event or behavioral modeling
→ no sampling
→ no (other) row
```

The Data API uses the same report-data layer and reporting identity as the Analytics interface, but a
specific API query still depends on requested dimensions, metrics, filters, quotas, and processing
state. BigQuery provides granular export data rather than a byte-for-byte copy of the GA4 interface.

# Freshness and late data

Recent report and API results can change for 24 to 48 hours while realtime, intraday, and daily
processing completes. Intraday results can temporarily have traffic-source gaps, interim attribution,
and stricter cardinality behavior. BigQuery daily tables can receive late events for up to three days
after the event date; events arriving after that window are not recorded.

# Canonical usage rule

- Use Reports for standard monitoring and recurring business questions.
- Use Explorations for analyst-driven investigation and segmentation.
- Use the Data API for programmatic retrieval of report-layer results.
- Use the Admin API for configuration management.
- Use Measurement Protocol for trusted server and offline collection that supplements tagging.
- Use BigQuery for event-grain reconstruction, custom SQL, and downstream data engineering.

No pair of these surfaces should be treated as universally equivalent without matching date range,
time zone, identity, attribution, filters, consent, freshness, retention, thresholding, and modeling
assumptions.

# Key distinctions

- property ≠ data stream;
- event ≠ user ≠ session;
- collection identity ≠ reporting identity;
- event ≠ key event;
- standard report ≠ Exploration;
- Data API ≠ Admin API;
- report data ≠ BigQuery event export;
- cookieless ping ≠ modeled user;
- privacy thresholding ≠ source-data deletion;
- retention ≠ report freshness;
- Measurement Protocol ≠ replacement for client tagging;
- linked product data ≠ unrestricted shared source data.

- production reconciliation of GA4 purchase revenue with Google Play and AdMob financial systems;
